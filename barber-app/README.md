# Джентльмен — PWA для мужской парикмахерской

Прогрессивное веб-приложение (PWA) для онлайн-записи к барберам: клиенты, мастера и
администратор в одном приложении. Устанавливается на домашний экран телефона, работает
офлайн, все данные хранятся в `localStorage`.

```
barber-app/
├── index.html          разметка: экраны, модалки, таб-бар
├── manifest.json       PWA-манифест (standalone, иконки, ярлыки)
├── sw.js               Service Worker: офлайн-кэш barber-v3 (включая фото)
├── css/
│   └── styles.css      токены светлой/тёмной темы и все компоненты
├── js/
│   ├── storage.js      localStorage, утилиты дат/телефонов, перенос гостевых записей
│   ├── media.js        встроенные фото, миграция старых URL и fallback
│   ├── pwa.js          установка, определение браузера и регистрация SW
│   ├── auth.js         авторизация, регистрация, CRUD сотрудников, доступность
│   ├── booking.js      услуги, слоты, создание/отмена/завершение/оценка записей
│   └── app.js          весь UI: экраны, календарь, модалки, обработчики
├── images/             оптимизированные JPEG салона и демо-барберов
└── icons/              28 SVG-иконок + PNG-иконки приложения
```

## Запуск

Любой статический сервер из папки `barber-app`:

```bash
cd barber-app
python3 -m http.server 8080        # затем http://localhost:8080
```

Приложение стартует на экране **«Записаться»**, демо-барберы уже добавлены.

Service Worker и установка требуют **защищённого контекста**: HTTPS либо localhost
на том же устройстве. Для проверки на телефоне публикуйте весь каталог `barber-app`
на HTTPS-хостинге (или используйте HTTPS-туннель). Обычный адрес локальной сети
`http://192.168.…:8080` годится для просмотра, но не для установки или офлайн-режима.
При открытии внутри iframe установка недоступна: используйте отдельную вкладку браузера.

**Где публиковать.** Нужен постоянный адрес: GitHub Pages (workflow уже в репозитории),
Cloudflare Pages, Netlify, Vercel. Временные хостинги вроде Cloudflare Drop не подходят:
через 60 минут сайт удаляется, а установленное приложение перестаёт открываться.
Пошаговая инструкция — в [корневом README](../README.md#публикация-где-держать-сайт).

## Доступы

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `ADMIN777` | `777` |
| Барбер: Артём Соколов | `artem` | `barber123` |
| Барбер: Данила Крылов | `danila` | `barber123` |
| Барбер: Марк Ефимов | `mark` | `barber123` |

Клиента можно зарегистрировать самостоятельно, а можно записаться **гостем** — без аккаунта,
указав имя и телефон. Гостевые записи хранятся по `guestId` и автоматически переносятся
в аккаунт при регистрации или входе (тост «Записи перенесены в аккаунт: N»).

## Возможности

**Клиент.** Выбор барбера (горизонтальный скролл с фото, рейтингом) → услуга из тех, что
оказывает мастер → дата в календаре с зелёными точками доступности → время (сетка 4 колонки,
шаг 30 минут, занятые слоты зачёркнуты). История визитов, статусы «Активна / Выполнена /
Отменена», повторная запись в один тап, оценка мастера после стрижки, редактирование профиля
(логин не меняется).

**Барбер.** Список своих записей с контактами клиента (имя, телефон, email), кнопки
«Выполнено» и «Отменить», выбор оказываемых услуг чекбоксами, редактирование доступности
по конкретным датам (календарь + слоты, «Выбрать весь день» / «Снять всё в дне»),
свой средний рейтинг. Клиентские вкладки мастеру недоступны.

**Администратор.** Вкладка «Сотрудники»: создание, редактирование, удаление, модалка
доступности (изменения сразу видны барберу и клиентам). Вкладка «Записи»: все записи одним
списком с фильтрами по барберу, услуге и дате (все / будущие / прошедшие), полные данные
клиента, отмена записи. Вкладка «Рейтинги»: сортировка барберов по среднему рейтингу,
количество оценок и прогресс-бар.

## Установка на телефон

Кнопка **«Установить приложение»** доступна в «Аккаунте» и как значок загрузки в шапке,
даже когда браузер ещё не прислал `beforeinstallprompt`. Она вызывает штатное окно
установки, если оно доступно, иначе открывает инструкцию для текущего устройства.

- **iPhone / iPad:** откройте HTTPS-сайт в **Safari**, затем «Поделиться» →
  **На экран «Домой»** → «Добавить». Если есть «Открывать как веб-приложение», включите его.
  Safari не поддерживает автоматическое окно `beforeinstallprompt`.
- **Android (Chrome / Edge):** кнопка установки либо меню браузера →
  «Установить приложение» / «Добавить на главный экран» → подтверждение.
- **Мессенджер / соцсеть:** сначала выберите «Открыть в браузере» или скопируйте
  адрес в Safari / Chrome. Встроенный браузер может не поддерживать PWA.
- **Встроенный предпросмотр:** кнопка предлагает открыть тот же сайт в отдельной вкладке.
- **HTTP / локальный HTML-файл:** приложение объясняет необходимость HTTPS;
  имитировать установку в неподдерживаемом окружении оно не пытается.

Приложение открывается в режиме `standalone` — без адресной строки, с учётом safe-area iPhone.
После события `appinstalled` и при standalone-запуске кнопки установки скрываются.
Отмена или ошибка штатного окна не блокируют кнопку: можно открыть инструкцию и повторить
установку через меню браузера. События PWA не сбрасывают введённые данные и фокус в формах.
Манифест и регистрация SW используют относительные пути, поэтому работают и в корне,
и в подкаталоге сайта.

## Фотографии

Встроенные фото салона и демо-барберов находятся в `images/` и загружаются с того же
сайта, что и приложение: внешний CDN не нужен. Шесть оптимизированных JPEG занимают
около 270 КБ и заранее попадают в офлайн-кэш, даже если галерея ещё не открывалась.
Источники фотографий — в [`images/README.md`](images/README.md).

При запуске известные старые URL демо-фото из Unsplash автоматически заменяются на
локальные пути в `bb_users` и `bb_bookings`. Пользователи, записи, рейтинги и графики
сохраняются; остальные пользовательские URL фото не меняются. Собственные фото мастера
по URL по-прежнему поддерживаются; рекомендуются доступные HTTPS-ссылки на изображение.
Для недоступного аватара показываются инициалы, в том числе в модалках.

## Хранение данных

| Ключ | Содержимое |
|---|---|
| `bb_users` | клиенты и барберы (включая услуги, рейтинг и график доступности) |
| `bb_bookings` | все записи |
| `bb_current` | текущая сессия: `{ id, role }` — данные всегда читаются свежими из `bb_users` |
| `bb_theme` | `light` \| `dark` |
| `bb_guest` | id гостя для гостевых записей |

Запись: `{ id, ownerKey, userId, userName, userPhone, userEmail, barberId, barberName,
barberPhoto, service, price, duration, date, time, status, rating, ratedAt, completedAt,
needsRating, createdAt }`, где `ownerKey` — `u_<userId>` или `g_<guestId>`.

## Обновление кэша

После правки любых файлов приложения поднимите версию в `sw.js`:

```js
const CACHE_VERSION = 'barber-v4';   // текущая версия v3; следующее обновление — v4
```

При активации нового Service Worker старые кэши этого приложения удаляются автоматически
(чужие кэши не затрагиваются), а пользователю показывается тост
«Доступна новая версия — перезапустите приложение». Полный набор файлов загружается
до активации: неполный офлайн-кэш не объявляется готовым. Статус подготовки виден в «Аккаунте».
После публикации обновления откройте приложение онлайн и перезапустите его; очищать
localStorage или сбрасывать демо-данные не нужно.

## Технические детали

- Чистый vanilla JS, без фреймворков, внешних библиотек и внешних запросов для встроенных фото.
- Редиректы хостинга. Cloudflare Workers/Pages отвечают на `/index.html` редиректом на `/`,
  а браузер не принимает от Service Worker ответ «через редирект» на открытие страницы
  (`net::ERR_FAILED`, «Не удалось получить доступ к сайту»). Поэтому `sw.js` сохраняет
  всё, что пришло через редирект, «чистой» копией (`cleanResponse`), оболочка лежит в кэше
  и как `./`, и как `./index.html`, `start_url` и ярлыки манифеста ведут на `./`, а редирект
  от сервера при наличии сети отдаётся браузеру как есть.
- Иконки — отдельные SVG-файлы, подключаются как CSS-маски (`mask-image`), поэтому
  наследуют цвет и одинаково выглядят на всех устройствах. Эмодзи не используются.
- Тема — CSS-переменные на `html[data-theme]`, переключатель в шапке и в настройках.
- Обработчики — делегирование событий на `document`, один ре-рендер на действие.
- Адаптив: колонка 480px на мобильных, 720px с двухколоночными блоками на десктопе.

## Регрессионные тесты

Из корня репозитория (Node.js 22+, Python 3):

```bash
npm ci
npx playwright install --with-deps chromium webkit
npm test
```

`npm run test:unit` проверяет миграцию фото, жизненный цикл установки, манифест
и стратегии офлайн-кэша без браузера. `npm run test:browser` запускает мобильные
сценарии в Chromium (Android) и WebKit (iPhone). Тестовый сервер автоматически
поднимается на порту 8080 и обслуживает приложение в `/`, в `/barber-app/` и в `/cloudflare/`
(там `/index.html` отвечает редиректом на `/`, как на Cloudflare Workers и Pages).
Для уже установленного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

Проверяются: запуск установленного приложения по `start_url` и ярлыкам онлайн и офлайн на хосте
с редиректами, фото без внешнего CDN, ещё не открытая галерея офлайн, сохранность данных
при миграции, инструкции iPhone/iPad/Android, iframe и встроенные браузеры, HTTPS,
штатная установка/отмена/ошибка, скрытие кнопок после установки и standalone-запуска.
Проверка критериев PWA через CDP выполняется только в Chromium.
